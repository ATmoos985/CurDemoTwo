# 2026-09-21 修复雷达拖拽失焦、缩放平移跳变与工位边界盲区记录

## 1. 发现的问题与隐患分析
1. **Pointer Capture 状态异常报错**：
   - 原代码在 `#radar-track` 轨道收到 `pointerdown` 事件时，调用 `winEl.setPointerCapture(e.pointerId)`，违反 W3C Pointer Events 规范，触发浏览器控制台 `DOMException: InvalidStateError` 报错，导致轨道点击与拖拽失焦卡死。
2. **滚轮缩放/画布平移后拖拽滑块视口突跳（Viewport Jump）**：
   - 原代码依赖固定的静态 `window._bedAnchorY`，在用户缩放（Wheel）或平移（DragMove）画布后，再次抓取雷达滑块时，画布视口基于过期的比例尺直接突跳数千像素，造成机台视口瞬间飞脱。
3. **大红框拦截鼠标事件导致画布穿透失效**：
   - 固定工位框 `bedStationGroup` 未设置 `listening(false)`，高层级的工位矩形直接拦截了鼠标悬停、框选与平移事件，导致下方裁片和画布无法交互。
4. **工位底切刀口切断线缺少动态米数数值**：
   - 裁切工位底部切断线缺乏动态实时坐标，操作员无法直观获取当前送料落料的下死点绝对位置。

- **`src/main/resources/static/index.html`**

  - **行 2293~2307**：新增 `dynBedBottomBadge` 动态切断线下死点标牌，并在工位组挂载 `bedStationGroup.listening(false)` 实现事件穿透。
  - **行 2387~2445 (`updateFabricScrollPosition`)**：
    - 废弃静态 `window._bedAnchorY`，改用动态屏幕视口锁存模型 `const anchorScreenY = (dragScreenBedY !== null) ? dragScreenBedY : (stage.y() + prevY * scale)`；
    - 同步更新顶部展开范围与底部切断线下死点 Y 轴标牌数值。
  - **行 2546~2628 (`setupRadarInteraction`)**：
    - 采用标准全局 `window.addEventListener("pointermove", ...)` 与 `window.addEventListener("pointerup", ...)` 范式，彻底消除 `setPointerCapture` 报错；
    - 拖拽启动时锁存 `dragScreenBedY`，拖拽全程强制机台屏幕视口恒定静止，布料以 60FPS 丝滑贯穿；
    - 拖拽结束时重绘疵点状态语义，且鼠标移出浏览器外绝不丢事件。
