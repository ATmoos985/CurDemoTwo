# 通用画布能力与场景接入设计

版本 0.1 · 2026-10-23。依据用户本轮纠正：服装、窗帘是业务场景，二维排料是共同能力；各场景复用完整画布。本文是源码盘点和实施基线，标为目标的接口尚未实现。

## 1. 产品关系与入口

生产入口保留任务管理、二维排料与切割、一维分切。窗帘、服装不再各占一个并列的生产工具入口；新建二维任务时选择场景或载入需求，再进入同一个工作台。任务创建后保存场景及规则版本，重新打开依然识别原场景，不能靠当前导航或文件名猜测。

场景差异通过需求编辑器、工艺规则、目标策略、检查结果和输出模板表达。切换场景不能只改标题：如果会改动轮廓、单位、旋转、纱向、需求数量或策略，必须先展示变更摘要，经原有草稿/预约检查后另建或更新任务；不覆盖已下达的方案快照。

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 业务场景 | 窗帘订单/服装款式尺码等需求解释、规则和操作术语 | 重新实现缩放、标尺、命中或直接修改求解器 |
| 排料与计算 | 标准问题输入、策略选择、算法执行、可行性和结果指标 | 操控 DOM、扣减库存、认定实际生产完成 |
| 画布底座 | 接收场景几何与显示状态、绘图、交互意图、视口及工具生命周期 | 判断库存是否可用、保存任务、发起报工、从 HTTP 加载业务 |
| 业务工作台 | 装配场景、算法和画布；执行状态锁、版本校验、持久化和失败恢复 | 把几何预检当作后端最终许可 |

`marker-demo.html` 保留为“服装齐套排料演示”，收纳到演示与帮助。旧地址和已经打开的页签仍有效，不替换用户正在编辑的二维任务。生产二维页面现有“新建任务 → 载入服装需求”继续使用；这不等于服装专业工艺已全部实现。

本批不会把窗帘、服装再各复制一套页面，也不会把完整生产画布替换为轻量演示预览。

## 2. 当前源码事实

| 链路 | 当前入口及实现 | 已共享与未共享 |
| --- | --- | --- |
| 生产二维 | `index.html` → `js/app.js` → `business/cutting/solver-client.js` → `business/cutting/workspace-scene.js` → `plugins/cad/cad-renderer.js` | 与演示共用 `canvas/nesting-renderer.js`；任务、连续工位、实际产出叠层由业务适配 |
| 服装生产需求 | `business/cutting/garment-demands.js` → 原需求编辑器 → 原排料/执行/报工 | 现有 M/L 示例轮廓可以进入生产工作台；尚未形成持久化场景模型 |
| 二维场景演示 | `nesting` 页面适配 → `canvas/nesting-scene.js` → `nesting/nesting-viewer.js` | 共用几何、舞台、标尺、测量；只读预览与生产手调不是同一套交互装配 |
| 服装齐套演示 | `nesting/marker-page.js` → `OptimizationSession` → `NESTING_2D` + `marker-shortening` → `mountNestingViewer` | 缩短长度是策略；末端/尾料标注当前写在 viewer 中，尚未抽成通用范围标注 |
| 验疵 | `inspection/inspection-canvas.js`、`inspection-model.js` | 复用标尺步长，舞台、坐标转换和疵点编辑主要独立实现 |
| 工作台页签 | `workspace/business-workspace.js` + `page-bridge.js` | 持续挂载 iframe 保留实例，是迁移期页面宿主，不是画布模块化已完成的证据 |

现有 `js/canvas/` 的五个文件已经承载场景模型、几何渲染、视口换算、命中图更新和平移缓存。不能重新发明同名底座；继续沿用并提取剩余通用职责。

主要缺口：`plugins/cad/cad-stage.js` 导出模块级 `stage/layers/groups`，默认读取 `core/state.js`；标尺/测量使用固定 DOM ID 与全局事件总线；`cad-view.js` 还有共享可变 `canvasView`。同一个 document 内挂载第二块画布会存在共享状态风险。当前 iframe 隔离避免了部分冲突，不能据此宣称支持多画布实例。

## 4. 模块和数据边界

继续使用 `canvas/`、`plugins/cad/`、`business/cutting/`，本阶段不拆独立仓库、不新建微服务。

- `canvas/`：中立的场景/几何/视口/渲染/命中及实例生命周期。允许依赖 Konva 或注入的渲染适配；不能导入业务、HTTP、库存、全局任务 state。
- `plugins/cad/`：兼容现有工作台DOM、菜单、工具装配；逐项将通用实现委托给实例对象。迁移期间保留旧接口，但新能力不得继续使用模块级舞台变量。
- `business/cutting/`：需求与方案转换、编辑许可、保存、执行、报工、实际产出叠层；只把显示数据和命令处理器交给画布。
- `nesting/`：演示输入、作业状态和结果选择。把唛架长度说明交给宿主，画布只绘制通用“范围/末端/未用区域”叠层。
- `inspection/`：跑布进度、缺陷草稿与保存状态；使用坐标适配保持现有验疵方向，不强制改业务坐标来迎合renderer。

场景显示数据沿用现有 `NestingScene` 形状：材料、region、placements、exclusions、leftovers、cuts、contours。迁移时明确区分材料局部坐标与工位偏移；结果轮廓已经旋转，不再依据 `rotationDegrees` 二次旋转。

后续显示模型需增加场景版本、实体稳定身份、范围标注和交互许可，但先在内部适配，不擅自修改已发布REST契约。任务ID、方案ID/版本、材料版本存放在宿主上下文；图层节点不持有可写库存实体。净面积/预计利用率/实际良品产出率由各自业务口径计算，画布只展示值、单位、定义和来源。

## 5. 目标实例接口（设计草案）

下列是迁移目标，不是目前可调用的SDK：

```js
const view = createCanvas({container, renderer, onIntent});
view.setScene(scene, {revision, capabilities, overlays});
view.setView({x, y, scale});
view.fit({target: 'region'});
view.setTool('measure');
view.setSelection(entityIds);
view.setVisible(false);
const snapshot = view.getView();
view.destroy();
```

`onIntent` 区分 `selectionChanged`、`viewChanged`、`proposePlacementChange`、`proposeDefect` 等。编辑意图携带实体ID、基准场景版本、变换及命令ID；宿主在忙锁、任务/方案版本与服务端校验通过后，把接受后的场景交回 `setScene`。通用画布不保存方案、不自动请求计算。失败时保留原图与建议位置，显示可恢复原因；迟到响应按命令和版本丢弃。

实例内部拥有舞台、图层、选择、工具状态、订阅、ResizeObserver和动画句柄；每次挂载返回独立对象。显隐只控制绘制/播放，不取消宿主正在运行的计算。`destroy` 幂等且只释放自身资源。事件按实例订阅，避免全局 bus 将一个窗口的缩放广播给所有窗口。

## 6. 场景接入规则

| 场景 | 需求与规则 | 共同底座 | 仍待实现或验证 |
| --- | --- | --- | --- |
| 通用二维 | 矩形/简单多边形、需求数量、材料/疵点、允许旋转 | 同一工作台、选择/手调/测量/刀序/执行报工 | 多材料结果统一切换及更完整几何编辑 |
| 窗帘切割 | 成品宽高/片数、来源订单、材料匹配、工位接续；工艺模板 | 同上，使用真实长卷坐标和加工区 | 专业成套/拼接/纹理对齐规则须独立建模，不能靠示例名称认定支持 |
| 服装切割 | 款式/尺码/衣片ID/每套片数、纱向、旋转、齐套要求 | 同上，绘制实际多边形和轮廓刀路 | 缩短唛架策略接入生产任务；尺码配比/缺片解释/场景持久化；缝份、条格、色差、叠层另行建模 |
| 验疵 | 材料身份、跑布位置、缺陷草稿/历史、避让区 | 复用坐标、视口、标尺、选择、工具生命周期 | 跑布跟随保持独立模式；替换前必须验证方向/位置/速度与保存一致 |

场景模板只能提出默认值，不能绕过原材料/几何约束。算法是否支持旋转、异形、齐套等由能力查询和请求校验确认；UI不能仅因出现按钮就宣称服务端支持。服装净面积/唛架占用长度与窗帘订单完成量分别解释，不能用“画布放满”代表任务完成。

一维继续使用同一业务工作台和公共显示组件，但一维组合表不是二维几何场景，不强行映射为裁片图来冒充统一。

## 7. 实施顺序与门槛

| 阶段 | 具体改动 | 必须通过的证据 |
| --- | --- | --- |
| C0（本批） | 源码能力盘点、纠正导航归属、保留原入口、任务操作收敛 | 原功能按钮/ID/handler保留；菜单可达；真实生产流程及页签切换验证 |
| C1 | 从 `cad-stage` 提取实例舞台/图层/数据源；实例化视口状态；旧生产接口薄适配 | 同document两实例不同原点/尺寸，互不串扰；隐藏/恢复/销毁/再挂载；现有长卷性能与标尺不退步 |
| C2 | 迁移标尺、测量、点选和工具互斥；统一输入事件与焦点仲裁 | 两实例测量独立、快捷键作用域、对话框/菜单不穿透、触控/键盘替代、视口保持 |
| C3 | 统一几何编辑命令、能力限制与版本；连接现有历史与服务端校验 | 碰撞/越界/纱向限制、撤销重做、预约锁、迟到响应；只读预览不能写库存 |
| C4 | 场景配置与任务持久化；窗帘/服装用同一画布；唛架策略接入真实任务 | 新建→保存→求解→执行→报工→刷新；完整尺码齐套、部分结果、不可比策略、旧任务兼容 |
| C5 | 验疵迁移、场景叠层、导出与AI意图接口 | 现场坐标不变、草稿/失败恢复、导出版本、AI受同一许可和审计约束 |
| C6 | 功能清单核销、性能/可访问性回归、清理旧实现 | 逐项证据取代“文件已搬家”；无重复底座、无遗留全局实例；完整原场景运行 |

每阶段单独提交和验收，不把 C0 导航调整当作完成画布抽离。已批准的库存、外部集成、认证等目标继续保留；新增通用能力不能为推进设计而削弱库存幂等/执行状态保护。

## 8. 验证方法与现有资产

单元资产：`cad-view.test.mjs`（坐标、缩放、网格与裁剪）、`cad-hit-graph.test.mjs`、`cad-pan-snapshot.test.mjs`（缓存正确性）、`nesting-scene.test.mjs`（模型与渲染）、`contour-workflow.test.mjs`（真实轮廓与业务适配）。测试数量以当批实际报告为准。

浏览器资产：`shared-cad.cjs`、`canvas-interactions.cjs`、`canvas-performance.cjs`、`canvas-rounds.cjs`、`inspection.cjs`、`garment-workflow.cjs`、`business-workspace.cjs`、`execution-workflow.cjs`。旧测试若仍依赖旧报工入口，先记录失败与当前链路差异，再迁移测试，不修改业务规则来让旧测试通过。

每个场景保存变更前后几何、数量、尺寸、视口和版本证据；自动检查正负方向、实际轮廓命中、刀路与导出一致。浏览器至少覆盖1366×768、1920×1080及390px入口可达。小屏能查看与操作菜单不等于完整CAD触控编辑已验收。

业务写入验收仅使用隔离库存。画布纯操作前后材料/任务/方案不应产生写入；真实执行/报工另按原用例验证。性能测试先记录当前基线和硬件/浏览器版本，再设定可比较门槛，不凭主观流畅或单次帧率宣布通过。

## 9. 本批边界

本批交付能力设计与入口纠正，保留原生产与演示功能。C1–C6 尚待逐步实施；同一文档多实例画布、完整场景模型、服装专业工艺、统一验疵和画布AI命令不能标为已实现。运行与提交证据记在《代码模块与实施进度》的当批记录。
