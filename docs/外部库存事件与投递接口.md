# 外部库存事件与投递接口

本期实现内置库存的事务 Outbox 与外部回执，不把事件投递当作完整 WMS 对账。库存是 `INTERNAL` 权威：对方消费已发生事实建立镜像/凭证，不能将同一事实当作新的本地扣料命令发回本系统。外部权威库存导入、预约凭证和采购/订单映射仍待接入。

## 事务与模块

- `business/cutting` 在业务事务内追加库存流水后生成 `InventoryEvent`；一笔事务一个事件，`id` 使用该组流水的 transactionId，`changes` 为完整的相关聚合前后值。事件序号独立于库存版本；只有真实新增流水才产生事件。
- `InventorySnapshot.outbox` 与文件库存原子替换；MySQL 的 `inventory_outbox` 与库存、报工、需求、移库单、流水共用事务。插入失败整单回滚；事件不可改删。V7 不将旧流水补发，`MIGRATION_OPENING` 与 `SYSTEM_DEMO` 不产生对外事件。
- `business/integration` 只做领取和回执状态转换，`IntegrationDeliveryStore` 保存独立状态，任何回执都不改变库存 revision。JDBC 按集成方行锁；文件模式独占回执目录，单应用实例。没有在库存事务内发 HTTP。
- 当前发布库存/需求、报工、复检、冲销、移库变化。不会虚构尚未接入的方案选定、执行下达或计算完成事件。`action` 是业务动作；`changes[].eventType` 可进一步区分入库与档案更新。

## 配置与凭据

默认关闭外部接口，仍记录新业务事件供以后接入。用服务进程环境配置：

```text
CUTDEMO_INTEGRATION_ENABLED=true
CUTDEMO_INTEGRATION_CONSUMER=external-inventory
CUTDEMO_INTEGRATION_TOKEN=<至少32字符的随机服务凭据>
CUTDEMO_INTEGRATION_LEASE_SECONDS=60
```

文件回执目录默认 `${cutdemo.state.path}.integrations`，可用 `CUTDEMO_INTEGRATION_PATH` 设置。MySQL 模式保存到同库独立 `integration_delivery` 表。环境配置要实际传递给 Java 进程；仓库 `.env` 不会自动被 Java 读取。不要把凭据写进代码、URL、浏览器本机存储、测试报告或日志。

只有 `/api/v2/integration-deliveries/**` 使用该专用 Bearer 认证，配置单个 consumer；调用参数不能选择其他 consumer 或绕过授权。未开启返回 503，凭据不符返回 401。生产跨主机连接必须经受控 TLS 入口，不能把这项认证说成旧 API、管理页面或多租户授权已完成。当前是外部适配进程主动拉取，没有任意目标 URL、自动 webhook 或自动转发凭据。

## 完整调用顺序

1. 外部适配进程持久化新的 `requestId`，调用 `POST /api/v2/integration-deliveries/claims`。正文 `{"requestId":"wms-attempt-001"}`，头 `Authorization: Bearer ...`。每次最多一个事件，按序处理；`EMPTY` 表示此时没有事件，该空请求不占用幂等键，稍后可再次轮询。
2. 返回 `LEASED`、事件和 attempt.token/expiresAt。整个事件按一笔外部事务处理，外部按 event.id 建唯一键，事件正文及外部凭证与更新一起提交。同事件重复到达返回原凭证；不能逐条 change 重复扣原料。单位和几何沿用流水，beforeJson/afterJson 代表事实前后值，不能把所有数字都当增量。
3. 外部事务提交后调用 `POST /api/v2/integration-deliveries/{eventId}/acknowledgements`：`{"token":"...","status":"ACCEPTED","externalReceipt":"WMS-凭证号"}`。收到成功后才清除本机待确认请求。确认操作不触碰本地物料余额。
4. 已知业务拒绝发送 `{"token":"...","status":"REJECTED","reason":"物料映射缺失"}`。序列停在该事件，处理原因后使用新 requestId 和 `retryOf`（拒绝的 token）显式重新领取。不会跳过失败事件继续后面的耗用。
5. 网络超时、进程中断或响应未知时保留原 requestId/正文重放。领取重放不续租，已过期返回 `EXPIRED` 和原事件；使用新 requestId 取得新 token，外部查询 event.id 的原凭证后确认。租约过期但尚无新领取时旧 token 也不能首次确认。至少一次投递依赖接收端幂等，不声称跨系统 exactly-once。

回执精确重放返回原结果；同 token 改结果/凭证/原因返回 409。旧拒绝回执精确重放不覆盖新尝试。新的首次确认必须匹配当前事件、最新尝试、有效租约及当前游标。进程崩溃后从已提交事件和持久化回执恢复；不得靠删除回执文件“修复”问题，否则可能重新投递全部事件。

## 查询与异常

`GET /api/v2/integration-deliveries?after=0&limit=20` 返回已配置 consumer、acknowledgedThrough、按序投递状态与 nextCursor/hasMore。limit 为 1–100；状态包括 PENDING、LEASED、RETRYABLE（租约过期）、REJECTED、ACKNOWLEDGED。列表不包含完整业务正文或领取令牌，事件正文随领取返回。

| 状态/错误 | 含义与处理 |
| --- | --- |
| 400 INVALID_INPUT | 字段、类型、分页范围无效；修正请求，不原样自动重试 |
| 401 UNAUTHORIZED | 专用凭据无效 |
| 409 DELIVERY_BUSY | 已被有效尝试领取；响应未知先查原 requestId |
| 409 STALE_ATTEMPT | 旧/错误令牌，查询并重新领取 |
| 409 DELIVERY_REJECTED | 处理拒绝原因后显式 retryOf |
| 409 IDEMPOTENCY_CONFLICT | 相同身份的正文/回执不同，不允许覆盖 |
| 409 STREAM_MISMATCH | 库存事件与外部确认记录不匹配，停机核对备份/外部凭证，不自动跳过或清空 |
| 503 INTEGRATION_STORAGE_UNAVAILABLE | 存储操作结果可能未知，保留原身份和正文重试 |

命令正文最多 8192 字节。JSON 拒绝重复键、未知字段、尾随内容及非字符串字段；空对象缺必填项失败。分页类型错误返回 400 而不是可重试的存储错误。

## 数据迁移和恢复

升级前已有报工和库存不自动转成外部新扣料事件。首次对接先明确双方期初基线，再从本期生成的事件顺序同步；外部原本已有的事件凭证须按 eventId 对应。事件聚合中的复检只重分类产出/需求，不再次扣原卷；冲销追加新事实且保留原流水关联。

备份与恢复必须一起保存库存快照/Outbox 和独立 delivery 状态。代码会核对首事件身份、已确认序号和尝试事件身份，拒绝不匹配的旧库存。该检查不是全量防篡改或外部余额对账。历史尝试保留在当前集成方记录中，暂没有归档压缩；本期仅单集成方，吞吐、长历史压测和多租户尚未验收。

## 验证入口

```sh
sh mvnw -Dtest=InventoryOutboxTests,IntegrationDeliveryTests,IntegrationApiTests test
sh mvnw verify
python3 integrations/inventory/test/live-smoke.py
```

`live-smoke.py` 使用 Python 标准库、最终 JAR、随机回环端口、临时文件库存和 SQLite 接收凭证，启动并重启自己的隔离进程；不会连接 8080。验证外部提交成功但确认丢失时按 eventId 去重、拒绝显式重试、过期令牌隔离、重启恢复以及投递期间库存文件完全不变。输出实际执行数量与证据目录，服务凭据仅存在进程环境，不保存到报告。

测试使用临时文件或独立 H2/MySQL 测试库，覆盖事件原子回滚、幂等、复检、期初不补发、文件独占、重启、并发领取、回执失败、迟到确认与真实 HTTP。独立审查发现的分页错误映射和数字被转换为 requestId 两项已加入回归。实际执行数量与本地交付状态记在《代码模块与实施进度》；没有客户 WMS 实例时，不把测试接收端称为已对接客户生产系统。
