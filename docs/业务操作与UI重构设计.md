# 业务操作与 UI 重构设计

版本：0.4，2026-10-23。状态：已接入真实多页签工作台；服装/窗帘归为二维业务场景，业务页面内部的操作收敛继续分批实施。

依据：已批准的《搭切平台模块化与业务管理设计方案》；用户最新要求：先设计所有业务操作，再设计前端，完整保留功能，表现克制、入口收敛。

本稿细化总体方案的工作台阶段，不替代算法、库存、外部集成、权限等未完成目标。以 `0574118` 多页签工作台为基础；盘点已完成本批后端与真实页面验证，具体交付状态和限制见《代码模块与实施进度》。

## 1. 先统一业务操作，再决定页面

每个操作必须有明确对象、输入、前置状态、副作用、成功证据和失败恢复方式。页面的职责是帮助用户完成这些操作。不能按“已有一个接口/插件”就增加一个全局按钮。

采用三层组织：

1. **业务入口**：任务、材料、分析、设置。全局只承担跨对象导航。
2. **对象空间**：任务详情、材料详情、执行单、报工单、库存单据。操作放在它实际改变的对象上。
3. **作业视图**：二维排料、一维分切、验疵等作业界面，提供完成当前步骤所需工具。服装、窗帘属于二维需求与工艺场景，复用同一画布，不作为与二维排料并列的生产模块。

画布能力现状、模块边界、目标实例接口及 C0–C6 迁移门槛见《通用画布能力与场景接入设计》。现有服装齐套演示保留在“演示与帮助”；生产服装需求已能进入二维工作台，但缩短唛架策略尚未接入生产任务，不能把入口归类当作场景统一完成。

主操作随状态变化；次操作始终有合理入口；低频参数按需展开。不能用隐藏必要步骤、删除功能、全部塞入“更多”、缩小字体和按钮来制造简洁。

## 2. 当前证据与能力边界

当前已经有四主导航，但 `index.html` 同时承担任务工具栏、阶段导航、需求、选料、机台、疵点、画布工具、记录与报工入口。同一业务对象多处出现，用户仍需理解实现分区。

来源核对：

| 来源 | 当前内容 | 本次设计如何使用 |
| --- | --- | --- |
| `static/index.html`、`js/business/cutting` | 任务、排料、执行、报工、草稿 | 主生产流程，不以整页隐藏代替拆分 |
| `static/js/plugins` | 材料、CAD、测量、刀序、打印、导出、设置、雷达 | 工具归位，保留事件和数据语义 |
| `static/linear.html`、`linear/LinearCutController` | 订单导入、异步计算、选组重切、撤销、导出 | 一维专用作业视图，业务报工仍待统一 |
| `marker-demo.html`、`nesting.html`、`demos.html` 等 | 唛架、场景、比较、输入结果导出 | 演示与帮助完整保留，不伪装生产任务 |
| 材料、移库、验疵、分析、设置页面 | 档案、实物操作、流水及能力信息 | 归入对应业务对象和子页 |
| `controller`、OpenAPI、`integrations/mcp` | 真实业务命令、标准计算、AI 入口 | 页面操作与 API 共用用例，不复制业务规则 |

辅助清单《UI现有控件清单.csv》最初抽取 334 处 button/summary/select 候选，来自 31 个文件；2026-10-28 R0 补入 counts.html 与 count-page.js 的 10 条盘点控件，目前共 344 条、33 个文件。HTML 为静态证据，JS 为动态模板候选；可能重复或包含模板表达式。它不覆盖全部快捷键、右键菜单、纯链接或画布手势，不能当作完整功能验收结果。迁移时同时核对本稿的功能族、事件处理器和真实浏览器行为。

R0 逐控件迁移状态与证据另见《重构/实施路线与验收》；旧候选数量不等于功能覆盖率。

能力标记：**已交付**＝可用代码及此前验收；**开发中**＝未发布；**待实现**＝总体方案目标。设计允许描述目标流程，但生产界面不得展示虚假的成功状态或可用按钮。

## 3. 业务对象和状态口径

| 对象 | 用户理解 | 状态/关键事实 | 不可混淆 |
| --- | --- | --- | --- |
| 任务 | 要生产什么、还差多少 | 草稿、待排料、待执行、待报工、需处理、已完成；并行执行单单独列出 | 计算完成不等于任务完成 |
| 计算作业 | 一次排料计算 | 排队、运行、取消中、成功、失败、取消 | 成功可能仍有未满足需求 |
| 方案版本 | 某输入快照下的排法 | 候选、待执行、编辑未验证、失效、取消、已报工/冲销 | 候选不占库存；人工改动不是自动可用 |
| 执行单 | 交给哪个工位做哪套方案 | 草稿、已下达、执行中、已报工、取消/过期；预约另有时间 | 预约、实际耗用分开 |
| 报工单 | 现场实际发生了什么 | 待核对、已记账、已冲销；复检事件追加 | 草稿/预检不记账；冲销不抹掉历史 |
| 材料单元 | 一卷/一块实物 | 账面数量、几何、库位、质量、预约、来源分别表达 | 隔离、已预约、同步失败不是同一种状态 |
| 库存单据 | 为什么改变库存 | 输入核对、提交结果待确认、已过账；错误以新单更正 | 不能直接编辑余额代替单据 |
| 同步记录 | 外部是否接收事实 | 待处理、已领取、可重试、拒绝、已确认 | 外部确认不等于余额对账通过 |

任务顶部展示净良品/需求、预约与剩余可排量；各工位并行状态保留。角色目前只作为操作视角设计，未实现认证前不能声称具备角色权限隔离。

## 4. 业务操作目录

编号用于迁移和验收。每行是一组同对象的相关操作；行内每个动词均需保留与验证。目标入口尚不代表新路由已经存在。

### 4.1 任务、输入和计算

| 编号 | 操作与必要输入 | 前置/副作用 | 成功证据与失败恢复 | 目标入口 / 当前状态 |
| --- | --- | --- | --- | --- |
| T01 | 新建、打开、查找、筛选任务；名称/型号/来源 | 新建先建立草稿；打开只读 | 有明确任务身份；不存在时阻断，不偷偷换成新任务 | 任务列表 / 已交付 |
| T02 | 增删改需求、Excel/JSON 导入、预览并应用 | 校验编号、尺寸、数量、轮廓；有效预约保护 | 导入错误定位行；应用有变更摘要；保留未确认输入 | 任务→需求 / 已交付 |
| T03 | 保存需求、编辑来源订单 | 版本冲突不得覆盖；已报工需求有约束 | 返回任务新版本；冲突允许重新载入核对 | 任务→需求页脚 / 已交付 |
| T04 | 本机草稿查看、恢复、另建、清理 | 与服务端保存分开；恢复不写业务库存 | 显示来源、时间、任务；清理前展示范围 | 任务列表→草稿；当前任务未保存提示 / 已交付 |
| T05 | 选母卷/料头、扫码、推荐、匹配需求、切换材料 | 只读匹配；核对型号、质量、可用量、预约 | 已选材料摘要；无法选用说明具体原因 | 任务→材料选择器 / 已交付 |
| T06 | 工位范围、进料起点、机台/刀缝/纱向/旋转/疵点避让 | 改动使当前方案需重算/校验；保护已下达方案 | 摘要可追溯到输入快照；非法项原位提示 | 任务→方案→工艺与加工范围 / 已交付 |
| T07 | 输入校验、生成方案、等待、取消计算、重试 | 纯计算不扣库；取消不是完成 | 实际引擎、状态、履约；失败保留输入和诊断 | 方案主操作与运行详情 / 已交付 |
| T08 | 查计算输入、结果、限制、降级原因、尝试记录 | 只读；无可测进度不造百分比 | 原始快照、状态及指标口径可追溯 | 方案→计算详情 / 已交付 |
| T09 | 方案列表、打开、比较、取消/恢复 | 查看不执行恢复；比较需同约束同口径 | 对比不可比原因；旧方案失效原因明确 | 任务→方案记录 / 已交付；各作业视图接入程度不同 |
| T10 | 拖动、旋转、增删排放、校验、保存调整版 | 不改变原方案；预约/执行时禁改 | 未验证显式标记；校验错误定位裁片 | 方案→编辑布局模式 / 已交付，统一版本体验待重构 |
| T11 | 选择方案、创建执行单、指定工位 | 再核对任务与材料版本；创建不是下达 | 执行单身份及待下达状态 | 方案主操作→执行单 / 已交付二维 |

### 4.5 分析、设置和集成

| 编号 | 操作 | 目标入口 | 真实边界 |

## 5. 六条必须设计并验收的完整流程

### 5.1 正常生产

任务列表新建 → 录入/导入需求并校验 → 保存任务 → 选择可用材料 → 核对工艺摘要 → 计算方案 → 核对履约与指标 → 创建执行单 → 下达预约 → 开工 → 实切/产出/余料核对 → 提交 → 回执 → 剩余需求继续安排。

每步展示输入来源与影响对象；查看详情不改变状态。候选方案阶段不扣库存；报工成功才展示实际产出率。

### 5.2 计算失败、未齐套及方案过期

失败保留输入 → 解释错误/不足 → 定位需求、材料或约束 → 修改后产生新计算。未齐套展示缺项，不用绿色“成功”掩盖。材料/需求被更新时旧方案保留只读证据，执行动作给出“重新核对并计算”，不能直接启用失效方案。

### 5.3 网络断开与重复提交

以下是所有写操作的目标恢复规范，不代表当前所有页面均已实现。报工队列与移库已有持久化恢复机制；复检 `quality-review.js` 当前仅在弹窗闭包保留命令，支持同页原请求重试，刷新会丢失身份与正文。复检持久化、跨页竞争与刷新恢复须在 UI-3 中补齐并专项验收。

提交前保存请求身份/正文 → 结果未知时进入待确认状态 → 禁止同对象新建冲突提交 → 查询或原身份重试 → 确认成功后清理待确认凭证。刷新、返回、跨标签页都不得丢失凭证。已确定的校验失败允许修改输入，未知失败不能假定未记账。

### 5.4 已报良品复检不良

从报工产出选择具体裁片 → 查看原良品/处置记录 → 选择转料头或报废 → 核对几何与原因 → 显示净良品减少、补产增加及材料去向 → 提交处置 → 原报工仍可查看。原卷耗用不恢复，也不再次扣减。

### 5.5 库存移动、盘点和找回

从材料详情或单据列表新建 → 核对账面快照 → 输入目标位置或实测值 → 显示逐项差异 → 原子过账 → 查看单据及流水。移库不改数量/质量；盘点差额单独记账；找回料头保留来源且先隔离。发现预约、坐标冲突或版本变化时阻断并指向相关对象，不清空测量内容。

### 5.6 外部同步拒绝

本地报工已记账 → 外部事件待接收 → 拒绝时保留本地事实和拒绝证据 → 修正映射/外部条件 → 显式重试同事件 → 确认外部凭证 → 对账另行执行。同步异常在单据中提示，不能把“重试同步”变成“再次报工”。

### 工作台与页签规则

按用户最新确认，左侧为业务导航，右侧为应用内页签和完整工作区。点击左侧打开或激活对应页签，二维排料、一维分切、验疵等保留现有完整画布、算法调用和工具，不使用简化 SVG 或模拟业务替代。服装齐套排料的独立演示页收纳到演示与帮助；生产服装切割归属二维任务。

当前 `/workspace.html` 持续挂载原页面实例：切换页签不重建画布、不重置视口和计算结果。任务深链接复用二维实例，切换对象沿用草稿确认与忙锁；页签隐藏暂停刀序/验疵播放，不取消计算，也不自动恢复播放。内部业务链接在同一操作台打开。此批不提供销毁页签，浏览器刷新仍遵循各页面现有恢复能力，不承诺恢复全部打开页签及内存状态。

### 页面容器规则

| 容器 | 适用 | 不适用 |
| --- | --- | --- |
| 完整页面 | 任务、排料、报工、验疵、库存单据；需要持续输入、分享地址、浏览器返回 | 为了少一页把它塞进多层弹窗 |

## 8. 克制的视觉规范

方向：紧凑的工业作业台。区分“输入、方案、现场事实”依靠明确标题、状态和单位，减少嵌套卡片、重复边框和大面积彩色背景。

- 色彩建议：页面 `#F5F7F8`、工作面 `#FFFFFF`、正文 `#24343B`、辅助文字 `#5D707A`、分隔线 `#D7E0E4`、主操作 `#08768F`。成功/警告/错误另用语义色且配文字；最终对比度要实测。
- 中文标题/正文采用系统无衬线字体，标题靠字号和字重区分；数字采用等宽数字，编号使用系统等宽字体。操作界面不额外引入装饰字体。
- 正文建议 14–16px、页标题 20–24px、表格行高 36–40px；键盘焦点清晰，触屏操作目标不小于 44px。不能为显示更多列持续缩小字号。
- 间距采用 4/8/12/16/24px；短摘要用轻分隔，不把每个数做成独立大卡片。表格优先呈现身份、状态、关键量和下一步；低频字段放详情。
- 唯一持续可见的业务识别线索是“对象身份 + 当前状态 + 下一步”。几何画布保留真实材质/疵点图例，其颜色不兼任页面操作含义。
- 页面切换和展开只用短暂功能性过渡，尊重减少动画偏好；不加入持续闪烁、装饰性进度或自动轮播。
- 1366×768 为完整桌面基准；1920×1080 利用空间增加工作面而不是拉长表单；390px 宽保留查看、确认、报工与恢复，复杂画布编辑有明确桌面提示，功能入口仍可找到。

### 9.3 真实业务操作的场景矩阵

以下场景在现有真实模块上逐步重组并验收。用户已否决替代完整画布的模拟原型；该原型退出交付，不作为新操作台或功能保留证据。

| 流程 | 默认画面 | 必须可演练的变化 | 主操作变化 |
| --- | --- | --- | --- |
| 任务到执行 | 需求未保存 | 空需求、保存、选料、计算失败、未齐套、材料版本冲突、有效方案、下达、开工 | 保存需求→选料→生成方案→创建执行单→下达→开工→报工 |
| 材料盘点 | 选定材料及账面值 | 未选料、未填写实测、无差异、差额、预约阻断、版本冲突、待确认请求 | 记录实测→核对差异→登记盘点→确认原提交结果 |
| 实际报工 | 执行中的工单 | 校验失败、分项面积不守恒、预检、结果未知、原键重试、成功回执 | 核对实际产出→确认记账→确认原提交结果→查看回执 |

业务验收在隔离库存调用真实 API。设计中的未实现能力保持未开放，不以固定演示结果伪装为实际计算、执行或库存操作。

## 10. 前端实现边界

1. 页面壳负责导航、对象地址、布局和加载态；业务模块负责加载对象、状态动作、提交和恢复；画布只接收场景及交互意图。
2. 复用既有 API 和命令身份。导航重构不能重置任务、重复运行计算或调用库存写接口。
3. 主操作依据服务端允许动作与客户端未提交输入共同计算；服务端仍最终校验。现有只有执行单具备较完整 allowedActions，其他对象需补齐，不能假定现在已经统一。
4. 草稿和待确认命令分开保存，按对象身份隔离。跨页竞争沿用现有锁与身份核对，不把整页全局 state 当成跨对象唯一状态。
5. 单位、状态文案、错误反馈、表单控件、详情容器共用规范；不把库存规则写进通用表格组件。
6. 不因本轮 UI 重构更换框架或求解算法。先在现有静态 ES modules 上迁移；确有组件状态瓶颈时另立有证据的技术决策。

验收必须包含：键盘操作、当前对象识别、一个显著主动作、必需操作两级内可发现、复杂表单不嵌套弹窗、零脚本异常、无主页面横向溢出（宽表内部滚动可接受）、数字单位/口径一致、失败不丢草稿、返回不加载错任务、浏览器刷新/跨页重试不重复记账。

验收使用临时库存；不向正式库存写入验收数据。真实测试报告执行/成功/失败/跳过数；功能保留率未逐项核对前不宣称“100% 保留”。最终整体完成还需核对总体方案中的独立计算、外部权威库存、认证、多租户、AI 与一维业务执行，不能只凭 UI 完整宣布目标完成。
