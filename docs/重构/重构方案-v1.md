## 1. 统一业务流程

```
需求导入 ─► 搭切任务 ─► 选料 ─► 排料计算 ─► 方案审核 ─► 下达执行单 ─► 工位裁切 ─► 报工 ─► 复检处置 ─► 入库/料头 ─► 对账
 (订单)     (合并订单)  (母卷/料头) (一维/二维)  (候选→定版)   (预约材料)      (按刀序)    (实切/产出)  (良品/报废)
```

- **任务类型只在“排料计算”一步分叉**：一维调用一维内核，二维调用矩形/异形内核；前后的需求、材料、方案、执行、报工完全同构。
- 一维的“序号组 / 车次 / 工位”是方案的一种**展示与执行分组**，在通用模型里表达为 `Layout.groups`，画布与执行单都按组展示。
- 每个状态推进都有单据：方案版本、执行单、报工单、库存单据。界面只是这些单据的操作入口。

### 统一的数据模型（契约层）

| 概念 | 二维 | 一维 |
|---|---|---|
| `Roll` 母卷 | 连续材料：幅宽 × 总长，已用长度，疵点（全局 Y 位置） | 同左 |
| `Demand` 需求 | 矩形/多边形 × 数量 | 宽度 × 数量 |
| `Layout` 排法 | 一段布上的件位置 + 切割线，**长度随排法变化**（如 4.2 m、6 m） | 一车上的分条（宽度区间）+ 刀位，**长度固定**（每车定长） |
| `Segment` 拉布段 | 沿卷长依次排开：排法 + 起点 Y + 拉布长度；段间可插入疵点避让 | 每车一段；连续同配置的车构成序号组 |
| `Plan` 方案 | 母卷上的拉布段序列 + 尾料 + 履约 + 指标 | 同左 |

二维的切割不是固定区域：每次拉布长度由排法决定，在连续的母卷上从已用位置往后依次排开，遇疵点避让，最后剩尾料转料头。一维是它的特例，即每段等长、分条贯穿整段。

画布只认识 `Roll + Segment + Layout`，一维、二维共用同一个画布组件。

### 画布能力要求（搭切的基础）

画布是一个连续的世界：整卷就是画布内容，不按工位切成多张图。

| 能力 | 要求 |
|---|---|
| 相机预设 | **工位**：对准当前拉布段（含前后相邻的布）；**全卷**：显示整卷。预设只决定初始取景，之后可自由缩放平移 |
| 全卷显示 | **整条**（默认）：一条连续的卷，缩放查看；**平铺**：按列（竖向）或按行（横向）折返，一屏看完。个人偏好设默认，工具栏可临时切换 |
| 缩放平移 | 滚轮以光标为中心缩放，拖动平移，`+ / −`，适应 |
| 精确比例 | 比例框直接输入 `1:N`（含常用预设），显示相对适应的百分比；按显示器 DPI 换算（默认 96 dpi，1 px = 0.2646 mm，可在偏好中校准） |
| 标尺与坐标 | 卷长方向标尺显示全局 Y（m），幅宽方向标尺显示 X（mm），刻度随比例自适应；状态栏实时显示光标的 X / Y |
| 标注 | 当前段的拉布长度、起止 Y、幅宽；一维显示刀位；标注随缩放自动隐藏或显示，文字大小不随缩放变化 |
| 方向 | 竖向（默认，沿用现有画布：卷长沿 Y 向下）和横向。只是显示变换：模型坐标始终是 X=幅宽、Y=卷长（mm），疵点、切割基准、报工回执都用这套坐标，切换方向不改变数据和算法；文字始终正向 |
| 母卷导航条 | 常驻底部的整卷比例尺。**已切的拉布段固定**（置灰 + ✓，可点击只读查看，工位不能移入）；**工位滑块**沿用现有设计：拖动移动工位（吸附下一段边界，否则按 100 mm 取整），拖右端调整拉布长度（受布台最短/最长限制，与工具栏长度框同步）；也可直接点击计划段跳转。工位偏离方案时标记“工位已手动调整”。排法图例显示“长度 × 次数” |
| 一维 | 长度方向只做示意压缩（分条贯穿整车），比例与标尺以幅宽方向为准，卷长标尺仍显示真实 Y |

正式实现沿用现有 Konva 画布（`canvas/`、`plugins/cad/`、`plugins/radar/`）的能力，重构重点是：画布只接收 `Roll + Segment + Layout` 数据和相机状态，不再直接读写业务状态；在此基础上补齐横向显示、平铺模式和 `1:N` 精确比例。

## 3. 一维序号组算法评估

### 现在的做法

1. **A 层 选花型**：按宽度汇总需求（不区分订单）→ 花型枚举 + 列生成 → 选型 MIP（最少卷数/余料，附加奇偶、对齐惩罚）。
2. **多起点**：需求顺序 × SCIP 种子 × 对齐 λ × 奇偶罚 组合出多个花型集。
3. **B 层 装配序号组**：把订单分配到每卷的刀位上，最小化“不同配置”数（= 序号组数）。有 Stage5 指派 MIP、LNS 邻域搜索、Set-Partition 精修、Phase2 全局集合划分、需求峰值打磨等多条路径。
4. **择优**：`DeterministicPlanSelector` 按组数、花型数、余料等排序选最好的。

### 判断

- **两阶段分解本身合理。** 带订单标识的花型最少化问题是 NP-hard，先选花型、再分配订单是工业上常见的做法，当前结果可用，**不需要推倒**。
- **“笨”的地方在于 A 层看不到订单。** 序号组数由“花型 + 订单分配”共同决定，但 A 层只看宽度，只能靠种子、奇偶、对齐这些代理指标去“碰”一个对 B 层友好的花型集。源码注释写明这些代理指标“已全部实测证伪”，种子取值也是按某份数据调出来的（“79 → 74–76”），存在对单一数据集过拟合的风险。
- **B 层路径重叠。** 约 1 万行代码里有 5 条以上的优化路径做的是同一件事，运行时开关约 50 个，通过 JVM 系统属性（`System.getProperty`）传递。这是把算法拿到其他项目时最大的障碍。
- **正确方向已有雏形。** `UnifiedSetPartitionSolver` 把 A+B 合并：列 = (花型, 整车订单配置)，目标直接是启用列数（= 组数）。但现在只在质量模式精修里用，列池靠枚举生成，规模一大就受限。

### 建议（分三步，每步都可单独停下）

1. **先建评测基准（algo-bench）**：收集 10–20 份真实一维数据，固定指标（卷数、余料、超产、序号组数、耗时）。没有基准，后面的任何“优化”都没法证明。
2. **参数显式化**：所有 `System.getProperty` 开关收进 `SolverOptions`，作为求解输入传入，删掉实测无收益的分支。这一步完成后算法目录即可整体拷走。
3. **统一模型转为主路径**：对 (花型, 订单配置) 做真正的**列生成**——定价子问题是带订单标签的有界背包，主问题 LP 求下界，再对受限列池用 CP-SAT/MIP 求整数解（price-and-branch）。用现有两阶段结果作为初始列（warm start），保证结果不差于现在。成功后可移除多起点和大部分 B 层路径。

如果第 3 步在基准上没有明显收益，就保留现有两阶段做法，只做第 1、2 步的整理。

## 4. UI 原则

- 参考主流工业软件（CAD/CAM 与 MES 的常见形态）：**左侧导航 + 中央画布/表格 + 右侧属性面板 + 底部状态栏**。
- 高信息密度：28 px 行高的表格、等宽数字右对齐、字段标签在左。
- 颜色克制：中性灰为主，一个主色（钢蓝），状态色只用于状态（就绪/运行/警告/异常）。
- 不在界面上铺解释性文字；解释放在悬停提示和帮助里。
- 每个页面只有一个主动作，放在固定位置（页面右上 / 工作台底部）。
- 工作台把面积留给画布：需求、材料、工艺不常驻侧栏，收成阶段条右侧的摘要按钮（如“需求 6 项 · 已排 99% · 缺 2”），点开是锚定弹窗，点外部或 Esc 关闭；有异常时按钮本身变色提示。右侧只保留方案指标与当前段属性。
- 生产页没有示例数据；空状态只提示下一步操作入口。

| 场景适配 | `app/js/model/roll-scene.js` | 方案（工位相对坐标）→ 整卷坐标；状态口径见下；排除取消、冲销与料头方案；“新工位”位于最后一段有效拉布之后 |
| 排料请求 | `app/js/model/solve-request.js` | 由任务、母卷、工位窗口组装 `/api/solve` 请求：剩余数量 = 需求 − 已完成 − 已预约；疵点按工位裁剪并外扩安全距离（复用 `forward-search.windowDefects`） |
| 页面 | `app/js/pages/*` | 任务、排料工作台、执行与报工、库存、跑布验疵、库存单据、复检处置、生产分析、能力展示、设置 |

**拉布段状态口径**（依据后端：方案只在报工时由 PENDING 置为 CONFIRMED，演示“重置母卷”会删除报工但保留方案状态）：

| 状态 | 判定 | 画布 |
|---|---|---|
| 已切 | 存在未冲销报工 | 置灰、固定，工位不能移入 |
| 候选 | 方案 PENDING | 正常显示，可重新计算 / 放弃 / 报工 |
| 已失效 | CONFIRMED 但无报工（重置遗留） | 虚线淡显，不计入锁定与指标，不能报工 |

真实写入：任务新建 / 编辑 / 导入；选料（母卷或料头）后按工位计算、重新计算、放弃候选、向后查找；执行单创建 / 下达 / 开工 / 取消；报工、冲销、复检处置；手动调整与刀序另存版本；一维分切组合计算与逐车出车；入库、移库、盘点、料头报废；跑布验疵、疵点作废留痕。偏好保存在本机。

**一维分切（定长二维）**：任务类型 `SLITTING_1D`，需求为分切宽度 × 整米卷长 × 卷数，任务另存左右切边、组合宽度范围与步长、超产上限。组合由 v2 计算作业求解；每一车是母卷上“切头 + 卷长”的工位，条从左切边起排开，起点自动向后避让条区内的疵点；后端按母卷档案重算疵点并用二维同一校验生成刀序后保存为候选，之后执行、报工、复检、库存与二维一致。

**母卷消耗口径**：连续母卷不能倒拉。工位起点在已用长度之后时，中间跳过的区段（避让疵点、向后查找）一并扣减并记入回执；之后若报工落在已计入的跳过区段内（先报后一工位），只抵扣该区段，不重复扣减；冲销按回执快照恢复。报工面板会先显示含跳过区段的扣减长度。

**有效性与疵点口径**：任务排料（`/api/solve` 带任务、一维出车）一律按材料档案重算工位疵点，不信任客户端传入；独立试算接口保持原样。`GET /api/cutting/tasks/{id}/plan-checks` 返回失效候选及原因（材料 / 疵点变化、任务改版、材料不在库），工作台标“需重算”并禁用报工、建单、下达、开工与调整。已登记母卷的疵点只能经跑布验疵追加或作废留痕，档案保存（`POST /api/rolls`）不能覆盖。演示“重置母卷”在有报工时一律拒绝，不再产生“已失效”遗留。

已知限制：多工位批量报工与刀路播放条未迁移。
