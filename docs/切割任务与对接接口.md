# 切割任务与对接接口

当前工作台以一个切割任务收集需求，换母卷或料头时保留任务与需求行编号。矩形裁片使用现有横切和二维直刀求解器；预览不扣库存，报工确认才记录产出、扣减母料、回收入库。

## 当前闭环

1. 新建任务，填写材料型号、裁片尺寸和总件数，可选填外部订单号。
2. 匹配材料：同型号料头先列出，母卷随后列出。候选是尺寸筛选，不保证可避开疵点，也不代表已满足全部件数。
3. 选定一块料头或一卷母卷，按当前工位生成方案。未排下的需求留在任务中。
4. 现场完成整份方案后报工，核对实际用料长度和回收料头尺寸、库位。
5. 回执按需求行编号累计完成量；同尺寸不同订单行分别记账。可继续换料排剩余数量，任务和报工在刷新、服务重启后保留。

任务要求一种材料型号。同型号匹配不代表允许跨批次、色号或质检等级混用；现场仍需核对档案。后续有明确限制时扩展需求的材料约束，不把批次规则藏在示例编号中。

## 工作台的保存操作

- 顶部“保存需求”保存任务与需求，不记录裁切产出。
- 每个工位实切完成后，点“报工保存”，核对用料与回收清单，再点“确认报工并保存”。成功后自动接续，报工记录可随时查看。
- 走刀预览只演示刀路，不代表实切或报工完成。存在待报工方案时，工位跳转与母卷导航会先打开报工窗口；选择“暂不报工”保留当前方案。
- 报工默认用料长度覆盖成品及默认勾选的回收料头末端；仍需核对实际值。服务端保留边界、重叠和库存校验，错误显示在确认按钮旁。

## 内部 HTTP 合约

沿用 `/api` 前缀与现有 JSON 结构，尺寸单位统一为 mm，面积为 m²。校验不通过返回 HTTP 400 和 `{ "message": "原因" }`。

| 接口 | 用途与约束 |
| --- | --- |
| `GET /api/cutting/tasks` | 已保存任务列表 |
| `POST /api/cutting/tasks` | 新建或更新需求；更新携带 `id` 和 `revision`，防止覆盖旧版本 |
| `GET /api/cutting/tasks/{id}` | 返回 `task`、按需求编号汇总的 `completed` 和 `reports` |
| `POST /api/cutting/material-candidates` | 按 `rollModel`、剩余 `demands`、旋转与纵切设置筛选在库候选，不占用或扣减库存 |
| `POST /api/solve` | 原有求解接口增加 `taskId`、`taskRevision`；需求数量为剩余量，不传总数别名 `count` |
| `GET /api/cutting/plans/{id}` | 读取未确认方案的请求与结果，含单位和坐标系说明，供 CAD 适配器消费 |
| `POST /api/cutting/plans/{id}/adjust` | 校验手调位置，保存新版本并取消原方案；不扣库存 |
| `POST /api/cutting/report-confirm` | 沿用 `planId`、`actualCutLen`、`finishedPieceCount`、`actualRemnants`、`location`；同一 `planId` 重试返回同一回执 |
| `/api/rolls`、`/api/rolls/{id}`、`/api/remnants` | 沿用母卷、疵点、料头档案接口 |

新建任务示例：

```json
{
  "name": "本次切割",
  "materialModel": "TC涤棉-B2026",
  "externalRef": "MES-ORDER-001",
  "revision": 0,
  "demands": [
    { "id": 7, "name": "主片", "width": 2000, "length": 1000, "quantity": 3, "allowRotation": false }
  ]
}
```

`externalRef` 是关联字段，不具备 MES 导入去重语义。需求行 `id` 在任务内稳定且唯一，不能用数组位置、名称或尺寸代替。已有报工的行不能删除或修改名称、尺寸，总需求不得小于已报工量。任务修改后旧版方案不能报工。并行方案在报工时重新检查剩余需求与材料可用性。

任务还可携带 `process`，保存工作台下次打开的工艺默认值：`bedLength`、`trimStart`、`cutOrigin`、`firstStageOrientation`、`allowRotation`、`allowLongitudinal`。求解实际参数仍由每次 `/solve` 请求携带；料头尺寸取库存档案。

报工回执增加 `taskId`、`sourceRemnantId` 和 `demandQuantities`，保留母卷用量、产出、实际回收料头及时间。料头报工的 `actualCutLen` 必须为 0，核销原料头；母卷报工扣减实切长度。回收料头沿用来源母卷、父料头与代际编号。

## 手动调整与版本

矩形横切、贯通切割方案可以拖动、旋转或移除裁片。修改后进入“待校验”，不能直接打印、导出或报工。当前预览支持最近 50 次撤销/重做；保存调整版后开始新一轮编辑历史。

“校验并保存调整版”保留用户指定位置，校验尺寸、旋转权限、材料边界、重叠、疵点禁入、卷头修边及贯通切割条件，然后重新生成刀序和候选料头。它验证可执行性，不搜索更优布局；当前仅支持 0.1 mm 矩形位置，不支持轮廓手调或刀缝。候选回收区域按新布局重新生成，实际回收仍在报工窗口勾选和核对。

```json
{
  "adjustmentId": "d08a71d4-4530-4ed3-9d83-6d4810a3eaa9",
  "pieces": [
    { "id": 1, "x": 0, "y": 200.5, "rotated": false }
  ]
}
```

`pieces` 是本次保留的原方案裁片完整列表。编号只能来自原方案，未传入的裁片从预览移除；尺寸、名称和需求归属由服务器继承，不能通过此接口新增或缩放裁片。坐标为工位局部左上角坐标，单位 mm。

`adjustmentId` 是客户端生成的 UUID，也是新方案 ID；相同编号、相同内容重试返回同一方案，编号冲突则拒绝。返回保存的 `CuttingPlan`，包含 `id`、`parentPlanId`、`version`、`request`、`result`、`status`。老方案兼容为版本 1，调整版为上一版加 1。事务内重新检查需求版本与材料事实，新版落库和原版取消一起成功或一起回滚。

报工使用新 `result.planId`。被取消的原版不能报工；需要退回旧版时从方案记录显式恢复，恢复仍检查需求与材料有效性。校验失败保留当前手调预览，可继续修改或撤销。

## 与外围系统的边界

工作台面积口径：主指标“预计利用率” = 裁片面积 / 预计用料面积，预计母卷用料包含裁片、候选回收区域及实际刀线的最远末端；料头按整块面积计算。展开明细中的“加工区占用率” = 裁片面积 / 完整加工区面积。未切下的整幅卷尾不作为损耗；回收料头不算成品面积。

`/api/solve` 的原有 `totalArea` 仍表示加工区面积，`wasteArea` 表示该加工区扣除裁片与候选料头后的未分配面积，不能直接当作实际损耗。报工回执的 `usedArea` 是实际用料面积，`processingArea` 为求解加工区面积；`utilization` = `pieceArea / usedArea × 100`。实际回收和损耗来自回执。旧回执缺少 `usedArea` 时由 `pieceArea + remArea + wasteArea` 还原分母。

- **MES**：后续通过任务接口导入需求、查询剩余量，通过报工回执推送产出。外部重试键、订单行映射、鉴权和回执确认由接入时补充；当前没有连接 MES。
- **CAD / CAM**：读取方案中的矩形裁片、切线与疵点。服务端方案坐标为所选材料/工位左上角局部坐标；母卷全局 Y = `windowStartY + y`。`cutOrigin` 是机床基准参数，输出前由 CAD 适配器明确变换，不能将屏幕像素传给设备。现有 DXF / G-code 仍是导出工具，未做真实设备联机与机床验收。
- **数据库**：任务、方案、库存和回执保存在同一版本化库存快照中。文件模式以临时文件替换保存，仅支持单进程；MySQL 模式通过事务与快照版本检查阻止覆盖并发更新。写入失败恢复内存状态。

## 明确的能力边界

- 每次方案使用一个材料来源，可跨多次方案完成一个任务；暂不自动做多卷、多料头联合优化。
- 生产工作台仍是矩形直刀裁切；通用试验入口的多边形排样能力与边界见 [标准排样接口](nesting-api.md)，不能当作已支持轮廓生产报工。
- 报工按整份方案确认，不支持部分合格、报废数量拆分或报工冲销。
- 未确认方案随库存快照持久保存，可从方案记录恢复；恢复时会重新校验需求和材料是否变化。
- 手工改动图形后须校验并保存调整版再报工，避免屏幕图形和服务端确认内容不一致。
- 演示案例只载入需求与工艺输入，不自动重置现有库存，也不把预制裁片当作已报工产出。

## 验证

`CuttingTaskTests` 使用临时库存文件验证料头转母卷续切、需求行独立记账、重复报工、并行方案超额拦截、任务版本、材料边界以及重启恢复。浏览器报工验证使用单独的 `cutdemo.state.path`，不扣减默认演示库存。
