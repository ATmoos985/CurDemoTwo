# 2026-11-20 加固二维求解契约适配与原生引擎运行时自动降级

## 背景与根因

用户截图复现场景：工作台加载 `1226 卫衣大货版 (DXF)`（`120:1 + 140:1`，8 件异形片，`1650×1600`，`工艺 距0 · 头50`），在用户全局设置选择了非 `left-top` 起刀原点（如 `right-bottom`）后，4 路并行求解全部被后端契约校验拒绝：`轮廓排料仅支持单块材料，使用 left-top 坐标基准和 none 首刀方向`。

沿请求组装、几何校验、引擎调度与后端降级全链路排查，共定位 7 类系统性求解脆弱点：

1. **CONTOUR 模式透传全局起刀原点**：`CuttingWorkbenchPage.tsx` 直接透传 `settings.startCorner`（如 `right-bottom`），触犯 `NestingValidation.java:41` 轮廓工艺必须 `left-top + none` 的硬契约。
2. **GUILLOTINE 模式直接透传 `pieceGap > 0`**：`CuttingWorkbenchPage.tsx` 与 `NestingStudio2DPage.tsx` 直接下发 `process.pieceGap > 0`，触犯 `NestingValidation.java:54`「矩形间距请使用工作台适配层」的 422 拒绝。
3. **亚 0.1 mm 浮点精度与手工旋转漂移**：`rotateShapeGeometry` 按 `0.01 mm` 取整且需求/多边形顶点未量化至 `0.1 mm`，触发 `SolverFactory.validatePrecision(0.1)` 的 422 拒绝；高密 DXF 顶点数超 128 或量化折返尖刺亦可能触发 `PolygonGeometry.validate` 拒绝。
4. **首端修边在 CONTOUR 下被静默丢弃、在 GUILLOTINE 下缺少上限夹逼**：未参照 `ContourWorkflow.java:38-39` 将异形 `trimStart` 转为顶部禁入区；当 `trimStart >= height` 时直刀模式直接 400。
5. **重复需求 ID 与越界疵点未净化**：手工增删/导入重复 ID 或越界疵点可直接击穿后端唯一性与边界校验。
6. **CONTOUR 件数/顶点上限缺少前端预检**：超 200 件或 10000 顶点时直接并发冲击 4 路后端引擎后全线报错。
7. **原生 C++ 引擎仅在缺失时降级，运行时崩溃未降级**：`SolverFactory.java` 原先只在 `!engine.isAvailable()` 时降级；若云端低内存容器发生 OOM（退出码 137）或运行库异常，任务直接 `FAILED`，未在 `allowFallback=true` 时切换至内置 Java 引擎。
