# MIT 公理设计组合解耦、全仓无环强门禁与只读周检工具落地（2026-11-26）

## 1. 背景与目标

在阶段 B 完成库存单快照拆锁、定点增量持久化与 `RemnantService` 垂直解耦后，复盘全仓 MIT 公理设计（独立公理）矩阵仍存在三类结构性耦合残留：
1. 后端存在 4 组业务类双向循环依赖、2 组契约子包循环依赖、1 处残余 `CuttingWorkflowService.confirm` 同步锁，以及两处重复的避疵扩边裁窗实现；
2. 前端 `useStudioStore.ts` 膨胀至 1,738 行且被 25 个生产文件直接扇入，存在 `useStudioStore.ts <-> workbenchDraft.ts` 与 `WorkbenchBoardCanvas.tsx -> boardPlacementValidation.ts -> workbenchUtils.ts -> WorkbenchBoardCanvas.tsx` 两组循环 import；
3. 缺少覆盖后端全仓业务类/2 级子包、前端 `frontend/src` 全图的通用 Tarjan SCC 无环强门禁，及可复用的只读架构耦合体检 CLI。

本轮通过三路独立工作副本并行推进并零冲突合入 `master`，一次性清零全部循环依赖、完成前端 Store 正交域切片并落地只读架构体检 CLI。

## 2. 变更清单与实质决策

### 2.1 后端阶段 A 解耦与全仓 Java 无环门禁（提交 `bab77f5`）

- **破除 `FabricSolveAdapter` ↔ `ContourWorkflow` 双向环**：

  - `FabricSolveAdapter.toLegacy(...)` 保留薄委托，`ContourWorkflow.java` 改调 `SolveResponseMapper.toLegacy(...)`。

  - 移除 `CuttingWorkflowService.confirm(CutReport)` 多余的 `synchronized` 修饰符；
