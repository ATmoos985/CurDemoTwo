# 2026-11-17 React 工作台重构与多线程并发架构变更日志

## 1. 背景与重构目标

　　基于 `reaction` 分支（`f220583`）新建独立 `react` 分支，使用 **React 19 + TypeScript + Vite 6 + Zustand 5** 对 `/app/` 工作台进行系统级重构，解决原有界面杂糅、示例分散、报工流程绑定过紧以及单策略串行计算的问题，围绕四条核心诉求完成交付：

1. **需求与纸样簇中心（`#/clusters`）**：统一管理固定廓形多尺码套系模板（实测 DXF 样板 `1226`、`20148D`、`3129` 的 110–160 码配比、定制板材、全屋窗帘与一维定长分条簇），支持实时 `.dxf` 上传解析入簇与自定义新建模板簇，支持单簇载入或勾选多簇追加混排。
2. **二维自由画布搭切工作台（`#/workbench`）**：默认提供**预设自由画布**（自定义幅宽 $W \times$ 长度 $L \times$ 件距）并保留可选“绑定实卷避疵”模式；剥离报工、回退、质量复检等记账操作，新增画布下方**多方案对比槽**，支持一键竞速比较并导出 DXF / G-Code 后选择性**“拿出去报工”**。
3. **一维定长分切组合台（`#/slitting`）**：默认固定卷长，**不显示整卷二维画布**，仅在显式勾选“规避实卷纵向疵点”时按需展开实卷纵向避疵车次；聚焦母卷幅宽、左右切边、组合宽范围、条宽组合 SVG 示意条、计划车数与超缺口核对。
4. **原生多线程并发计算架构**：后端 `OptimizationService` 工作线程池默认容量升级为 `6` 线程并发、队列容量 `32`；前端支持 2D 最多 5 套策略、1D 3 套策略并发竞速求解。

## 2. 关键设计与变更文件清单

### 后端并发增强
- [OptimizationService.java](src/main/java/com/example/cutdemotwo/business/optimization/OptimizationService.java)：将默认 `@Value` 参数调整为 `workers=6`、`queueCapacity=32`（支持多求解作业在不持有对象锁下并行执行，各原生引擎与 OR-Tools 独立临时目录隔离）。
- [application.properties](src/main/resources/application.properties)：配置 `cutdemo.jobs.workers=${CUTDEMO_JOBS_WORKERS:6}` 与 `cutdemo.jobs.queue-capacity=${CUTDEMO_JOBS_QUEUE_CAPACITY:32}`。
