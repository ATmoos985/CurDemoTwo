## 二、M5 Tier 5 四轮白盒对抗实锤修复的 8 项关键缺陷

1. **MES `/api/v2/mes/*` 无条件白名单越权暴露与双认证死锁（R1 修复）**
   - **根因**：`AuthSecurityFilter.isWhitelisted` 曾无条件放行 `/api/v2/mes/*`，导致匿名或低权限凭证可绕过 RBAC/Agent 校验；同时若生产开启 `cutdemo.auth.enabled=true` 与 `cutdemo.mes.auth-required=true`，前端已登录排产员在点击「下发 MES 派工单」时无独立 `mesToken`，触发双认证互斥死锁。
   - **修复**：`AuthContext.java` 新增已认证系统主体 `MES_INTEGRATION_PRINCIPAL`（`authenticated=true`）；`AuthSecurityFilter.java`（714 行）移除白名单并精确匹配 `isMesEndpoint` 前缀，以 `MessageDigest.isEqual` 常量时间校验 `Bearer <mesToken>`，否则严格执行 JWT + RBAC（`PLANNER`/`OPERATOR`/`ADMIN`，`orders` 限 `PLANNER`/`ADMIN`，`dispatch-packages` 对合法用户只读）及 Agent 隔离（写接口一律 403、读接口需 `INVENTORY_READ`）；`StudioWorkflowController.java` `verifyMesAuth` 对 `AuthContext.current().authenticated()` 放行并保留本地免登模式的 `503`/`401` 语义。同步扩充 `AuthSecurityFilterTests`、`SecurityAndAuditIntegrationTests` 与 E2E `verify-auth-rbac-agent-audit.mjs`（第 35 项 `T2-F11-06`）。

2. **JWT 非规范 Base64URL 末位 padding-bit 签名变体与填充篡改（R1b 修复）**
   - **根因**：`AuthService.java` 原采用 `token.split("\\.")` 且先解码签名字节再比较 `MessageDigest.isEqual`，会忽略 32 字节 HMAC-SHA256 签名第 43 个 Base64URL 字符的低 2 位 unused padding bits（如 `'Y'` 改为 `'a'` 仍通过校验），且未拦截 Payload 中非规范编码或 `=` 填充；`T2-F11-01` 仅替换末位为 `'a'`/`'b'` 亦存在 1/16 碰撞概率。
   - **修复**：`AuthService.java`（455 行）改用 `token.split("\\.", -1)` 拒绝对空段及非规范 Header 的解析，对 `Payload` 验证 `=` 禁用与重编码一致性，并对 `Signature` 直接以规范无填充 Base64URL 字符串执行 `MessageDigest.isEqual` 常量时间比对。同步新增 `AuthSecurityFilterTests.rejectsNonCanonicalBase64UrlJwtVariantsAndPaddingTampering` 并将 `verify-auth-rbac-agent-audit.mjs` `T2-F11-01` 升级为遍历同高 4-bit 组全部 3 个变体。

3. **热冷分离 `LIKE` 通配符未转义与业务/对账/报表全表加载回流（R1 修复）**
   - **根因**：`JdbcColdArchiveQueries.java` 的 5 处 `LIKE ?` 查询未转义 `%`/`_`，允许异常或恶意通配符触发全表 JSON 反序列化；同时 `ColdStateQueryBridge.reconciliationReports`、`CuttingExecutionAndReportService.reverseReport`、`MotherRollSpatialMapQuery`、`ProductionReportService`、`StudioSchemeViewSupport`、`FabricCutController` 及 6 个活跃业务调用点仍调用全量 `listSchemes()` / `listAllSchemes()` / `getMotherRolls()`。
   - **修复**：`JdbcColdArchiveQueries.java`（788 行）统一新增 `ESCAPE '!'` 转义工具并将 `findFirstMatching` 改为 `ResultSetExtractor` 流式早停，新增 `findSchemesForPlanIds`、`findActiveSchemesByPlanId`、`findSchemesByRollId`、`querySchemes`、`countActiveSchemesForTask`、`listMotherRollsPage`；`ColdStateQueryBridge`、`CuttingExecutionAndReportService`（957 行）、`MotherRollSpatialMapQuery`、`ProductionReportService`、`StudioSchemeViewSupport`、`FabricCutController`、`RemnantService`（835 行）等全面下推至热池或索引/分页 SQL。`HotColdMemoryScaleTests` 通过 `ResultSet` 代理实证 `findSchemeByIdempotencyKey("%")` 拉取 `0` 行、`reconciliationReports` 不触发全表扫描。

4. **`WorkbenchTaskViewSupport.plannedQuantitiesForTask` 遗漏触发冷方案全表扫描（R1b 修复）**
   - **根因**：全仓排查发现 `WorkbenchTaskViewSupport.java:32` 的 `plannedQuantitiesForTask` 仍调用 `tx.listSchemes()`，在热冷模式下退化为 `JdbcInventoryStore.listAllSchemes()` 全表读取。
   - **修复**：替换为 `tx.listActiveSchemes()`（直读内存热池 `kernel.schemes`），并在 `HotColdMemoryScaleTests.workbenchTaskSummaryAndPlannedQuantitiesDoNotScanFullColdSchemes`（220 条冷 `COMPLETED` 方案压测）实证调用 `plannedQuantitiesForTask` / `buildTaskSummary` 时 `scheduling_scheme` 读取 `0` 行且 SQL 计数为 `0`。

5. **DXF 图层关键词无边界子串碰撞与 AAMA BLOCK 丢弃内孔（R2 修复）**
   - **根因**：`dxf-geometry.js` 原对 `outerLayerKeywords`（含 `'CUT'`、`'1'`）与 `holeLayerKeywords`（含 `'CUTOUT'`、`'11'`）执行无边界 `.includes()`，导致 `'CUTOUT'`/`'CUTOUT_1'` 误命中 `'CUT'`、`'11'`/`'HOLE_1'`/`'DRILL_1'` 误命中 `'1'`，不仅绕过内孔归属与穿刺校验，还在 `dxf-parser.js` AAMA BLOCK 分支中使 Layer `'11'` 内孔被误拆后丢弃。
   - **修复**：`frontend/src/lib/nesting/dxf-geometry.js`（848 行）与 `dxf-parser.js`（811 行）导出统一常量与 `matchesLayerKeywords`/`classifyLayerRole`：纯数字仅整串精确匹配、纯 ASCII 字母按完整词 token 匹配、混合词采用边界正则、双边冲突优先仲裁弱外框词（`CUT`/`裁切`/`PROFILE`）归为内孔；`dxf-parser.js` AAMA BLOCK 通过 `includeMatcher` 放行 `'1'` 与全部符合规则的内孔层并继续屏蔽 `'14'`/`'8'`/`'7'`/`'2'`/`'0'`。

6. **DXF 内孔穿刺检测盲区（BBox 越界、跨凹口与岛中岛嵌套逃逸，R1 + R3 修复）**
   - **根因**：R1 发现 `buildContourShapesWithHoles` 在寻父循环时遇 BBox 不包含即跳过导致越界穿刺漏判；R3 进一步发现即便设置了 `parentIndex >= 0`（如孔 H2 位于外框 A 内但穿刺岛屿 B 边界）也会跳过穿刺检查，且 `if (ring.parentIndex >= 0)` 先于 `if (ring.piercesOuter)` 命中从而漏放穿刺孔。
   - **修复**：`frontend/src/lib/nesting/dxf-geometry.js`（848 行）封装 `ringPiercesOuter`（BBox 剪枝 + 严格包含排除 + `segmentsCrossOrTouch` + 顶点/边中点/探点落入判定），在 `buildContourShapesWithHoles` 对全量纯内孔环校验其与所有非纯孔外环/岛屿环（排除严格位于其内部的合法岛屿及默认层奇数深度隐式内孔）是否穿刺，并将 `if (ring.piercesOuter)` 置于角色分配最前优先标记 `'ignored'` 与告警。独立 Node 探针（含 4a/4b、三层嵌套、默认层混排、无顶点落入横跨、贴边穿刺共 6 组强对抗场景）实证穿刺 100% 拦截、合法岛屿与安全孔零误杀。

7. **需求模板库全链路静默丢失 DXF 内孔 `holes` 与净面积双倍扣孔回归（R3 修复）**
   - **根因**：DXF 导入向导可识别内孔，但后端 `DemandTemplate.SizeGeometry` 与前端 `ClusterTemplatePiece`、`ClusterCenterPage.handleConfirmDxfCluster`、`templateHelpers.{parseDxfToDemandCluster,expandClusterToDemands}` 全链路丢弃 `holes`；同时扩展 `nesting-scene.js` 的 `shapeArea` 扣孔时需同步对齐 `benchmark/problems.mjs` `netShapeArea` 避免双倍扣孔。
   - **修复**：后端 `DemandTemplate.java`（78 行）扩展可选 `holes`（`@JsonInclude(NON_NULL)` 兼容旧无孔 JSON 与 3 参构造器），`StudioDemandPoolService.java`（559 行）`saveTemplate` 前置 `PolygonGeometry.validate` 拦截非法孔并返回 HTTP 400；前端 `studioTypes.ts`、`ClusterCenterPage.tsx`（848 行，`PieceMiniSvg` 改用 `<path fillRule="evenodd" />` 镂空预览）、`templateHelpers.ts`（521 行，在 `pairMirror` 镜像时调用 `mirrorVerticesX` 与 `ensureCw` 同步生成右片 CW 内孔）全链路打通；`nesting-scene.js`（122 行）`shapeArea` 扣孔且 `benchmark/problems.mjs`（324 行）`netShapeArea` 委托 `shapeArea`。经 `SchedulingStudioWorkflowTests`、Vitest 端到端链路及 R4 隔离端口 `18993` 真机 HTTP（模板持久化 → 镜像展开 → 2D 求解 → 落库 → R12/LWPOLYLINE/AAMA/PLT/NC 全格式 CAM 导出含孔）实证通过。

8. **BOM 根套数 `bomRootQty` 非法输入静默兜底放行（R1 修复）**
   - **根因**：`expandBomRows` 与向导弹窗 `DemandImportWizardModal.tsx` 对 `<= 0` 或非数值 `bomRootQty` 使用 `Math.max(1, ...)` 静默修正，未阻断错误导入。
   - **修复**：`frontend/src/lib/domain/demand-import-schema.js`（677 行）在 `expandBomRows` 中显式校验非法非空 `bomRootQty`，推入 `INVALID_BOM_ROOT_QTY` 错误并立即阻断；`DemandImportWizardModal.tsx` 改用 `string` 状态保留原始输入并交由引擎校验；`demand-import-engine.test.ts` 新增边界测试覆盖。
