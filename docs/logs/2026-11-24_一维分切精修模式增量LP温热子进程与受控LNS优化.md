## 核心改动与真实算例实测对比（精修模式）
1. **GLOP 增量加列热启动**：`ColumnGenerationSolver.IncrementalMasterLP` 复用同一 GLOP `MPSolver` 实例，每轮定价仅追加新列变量与系数，`added == 0` 固定点立即收敛并正确释放 native 内存。
2. **温热常驻隔离 Worker 子进程池**：`LinearSlittingSolverEngine` 保留独立 JVM `-Xmx` 隔离、50ms 看门狗与超时/取消强杀进程树，支持空闲池（上限 2）复用已加载 OR-Tools 的温热子进程，`@PreDestroy`/`AutoCloseable` + shutdown hook 双重清理。
3. **精修模式受控 LNS 与预算治理**：A 层封顶 40% 预算，B 层按剩余时间动态分档设定确定性 SCIP 节点上限并渐进两段式压缩序号组，单调不劣化车数与废料。
4. **6 个系统真实算例实测对比（车数与最高利用率 100% 守恒无劣化）**：
   - `board` (4 单)：`1,696ms → 120ms`（**-92.9%，14.1×**），利用率 97.54%
   - `curtain` (4 单)：`2,170ms → 544ms`（**-74.9%，3.99×**），利用率 96.43%
   - `film-t10-17` (反射膜 17 单)：`17,850ms → 10,286ms`（**-42.4%，1.74×**），利用率 95.00%
   - `film-t29-50` (反射膜 50 单)：`91,327ms → 56,035ms`（**-38.6%，1.63×**），利用率 95.06%，**排刀 34 → 32（-2）**
   - `film-t29-85` (反射膜 85 单)：**`120,164ms TIMEOUT → 90,411ms FEASIBLE`**，利用率 95.20%，**精确序号组 85 → 67（-18 组 / -21.2%）**
