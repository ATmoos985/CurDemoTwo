# 全量 React 化与历史旧代码彻底剔除交付（2026-11-25）

## 1. 背景与目标

本轮以单一现代 React + TypeScript + Vite SPA 为唯一前端架构，分四个阶段完成全仓历史经典页面、旧兼容 React 页面、后端纯旧一维宿主与零调用旧接口、旧静态 JS/外链三方库与失效浏览器脚本的彻底剔除与收口：
1. **Phase 1 & 2（经典前端资产瘦身与旧静态测试清理）**：彻底删除 17 个经典原生 `.html`、24 个经典 `static/css/**`、86 个非 React 依赖闭包旧静态 JS、22 个纯经典 JS 单测与 22 个纯经典浏览器脚本，并将 1.62 MB 原始 DXF 样本迁出生产静态目录至 `src/test/resources/fixtures/dxf/`。
2. **Phase 2 & 5（后端旧一维宿主与零调用旧接口清理）**：删除旧一维 `com.example.cutdemotwo.linear/**` 及测试，收紧 `ModuleBoundaryTests` 移除 `legacyLinearFiles` 白名单（强制全仓除 `algorithm/slitting/` 外严禁引用 `changyang.*`）；基于全仓（现代 React + 静态闭包 + MCP + Inventory Outbox + Benchmark + Dockerfile）端点审计，清理 `FabricCutController` 中确认零调用的 4 个纯旧端点（`GET /api/scenario/{id}`、`POST /api/cutting/slitting-cars`、`POST /api/solve`、`POST /api/toolpath/optimize`）及独占死类 `ScenarioOneService`、`ToolpathRequest`，同步清理 `AuthSecurityFilter` 规则并将降级测试等价迁移至 `/api/v2/optimization-jobs`。
3. **Phase 3（现代页报工冲销补齐与 5 个旧 React 兼容页下线）**：在 `ResultsCenterPage.tsx` 与 `ReconciliationPage.tsx` 补齐符合后端契约（底层 `planId`、原因 1–500 字弹窗、全量复检历史拦截 `dispositions.length === 0`、1D 多车方案 LIFO 逆序串行冲销）的「冲销报工」能力；切断现代页指向 `#/quality` 与 `#/task/new` 的残留旧链；删除 `TasksPage`/`TaskEditPage`/`ExecutionCenterPage`/`QualityPage`/`AnalysisPage` 及其 260 行专属样式，将 5 条旧路由收敛为轻量自动重定向（零旧页 chunk），同步更新现代浏览器脚本并删除 6 个旧路由脚本。
4. **Phase 4（全面迁入复用静态模块与三方库至 `frontend/` 并消灭 `static` 历史目录）**：解耦剥离 `slitting.js` 与 `task-form.js` 冗余传递耦合（级联再删 4 个旧静态 JS + 5 个旧 React 页独占 JS），将剩余 31 个纯计算 `.js` 迁入 `frontend/src/lib/{core,canvas,domain,nesting,model}/`，将 `konva.min.js`（v9.3.18）与 `xlsx.mini.min.js`（SheetJS CE 0.20.3）迁入 `frontend/src/vendor/` 由 Vite 统一打包/懒加载分包，将 `app.css`/`index.html`/`garment-shirt-gap-fill.png` 迁入 `frontend/` 由 Vite 直接输出至 `src/main/resources/static/app/`，彻底删除 `static/js/`、`static/app/js/`、`static/app/dist/`、`static/vendor/`、`static/konva.min.js` 与 `@static/*` 别名，同步升级 `Dockerfile:42`、`SiteEntryTests`、`AuthSecurityFilterTests`、`module-boundaries.test.mjs` 及清理 13 个孤儿浏览器脚本。
