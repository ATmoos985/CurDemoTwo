# 2026-11-23 算法内核 Phase 0：口径统一与死代码清理

## 变更目标
完成内核算法解耦演进的 **Phase 0（口径统一与死代码清理）**，在不改变既有对外 API 与业务行为的前提下，消除双引擎默认口径漂移、清理无效热路径几何死代码并关闭一维旧内核默认落盘行为。

## 关键决策与改动说明
1. **清理死代码**：移除 `JavaIrregularSolverEngine` 未使用的 `forbiddenArea` 及无效 `Area.add` 运算。
2. **统一 `startCorner` 默认基准角**：在 `EngineGeometry` 新增 `DEFAULT_GUILLOTINE_START_CORNER = "right-top"` 与 `normalizeStartCorner(String)`，对齐 `PackingSolverService`、`JavaGuillotineSolverEngine` 与 `SolveRequest` 的默认口径，保持 `CONTOUR` 模式 `"left-top"` 契约不变。
3. **统一余料最小尺寸下限**：移除 `JavaGuillotineSolverEngine` 中硬编码的 `Math.max(100, ...)`，直接使用请求中的 `minReusableWidth` / `minReusableHeight`，与 `PackingSolverService` 对齐。
4. **统一几何容差常量**：在 `EngineGeometry` 新增 `AREA_EPS_MM2 = 0.001`，与 `COORDINATE_EPS_MM = 0.001` 一并作为公共常量源，收拢各异形引擎与校验器中的重复字面量（保持 `DeepnestSolverEngine` 的 `0.5×` 严格容差语义不变）。
5. **控制一维旧内核默认落盘**：`SolveReportWriter.create()` 改为默认关闭（仅在 `cutting.report.enabled=true` 时写盘，支持 `cutting.report.dir` 覆盖目录），避免求解期间隐式向宿主机 `logs/` 写文件。
