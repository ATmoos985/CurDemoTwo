# 料头优先推荐

在裁切作业的“选择用料”窗口点击“计算料头推荐”。系统读取当前全部剩余需求、工艺及同型号可用料头，对候选逐块调用现有求解内核试排。界面展示建议先用的料头、库位、具体可切需求与件数、切后剩余需求、裁片面积、整块料头利用率和刀数。

选择推荐后仍需核对并确认装载；已有未报工预览需要明确确认清除。装载保留整批需求及已有合格完成量，随后生成正式方案并按原流程报工。合格报工后再匹配剩余需求，可以继续使用其他料头或母卷。

## 计算范围

- 同型号、AVAILABLE 且单件尺寸可能容纳的料头进入候选；尺寸初筛不代替排料。
- 优先评估面积较小的最多 8 块，每块求解时限 1 秒。显示已评估数量、总候选数量和未评估数量；失败和未排入均不代表数学上无解。
- 各块独立使用同一批剩余需求，互为备选，不能相加作为多料头分配方案。
- 先按可满足的需求面积从大到小排序，再按整块料头利用率从高到低、刀数从少到多及料头编号排序。利用率分母为整块料头面积，刀数为试排刀序数量，不代表实际机台节拍。短时搜索不保证全局最优，也不比较不同切割策略。
- 加工区按整块料头计算，实际机台是否容纳仍需核对；继承当前修边、起刀基准、首刀方向、旋转和回收阈值。库存疵点由服务器读取，带疵但无坐标的料头不推荐。
- 仅横切时，布料业务适配层只排原始宽度等于料头幅宽的需求，其余需求保留并显示原因；正式排料使用相同规则。通用标准内核仍要求横切输入全部等幅。

## 数据边界与接口

`POST /api/cutting/remnant-recommendations`

请求包含 `input`（沿用 `SolveRequest` 的材料型号、剩余需求、工艺设置以及可选任务编号/版本）和 `completedBaseline`（当前任务已合格报工数量）。可以分析未保存草稿，不会隐式保存任务。

返回 `candidateCount`、`evaluatedCount`、`deferredCount`、`inventoryVersion`、`recommendations` 和 `unavailable`。每个推荐含库存快照 `stock`、`pieceCount`、`pieceArea`（m²）、`utilization`（百分比）、`cutCount` 和按稳定需求编号关联的 `lines`。每行保留 `requested`、`placed`、`remaining`，这里的 remaining 是该备选全部合格完成后的预计剩余，不是已经扣减的业务数量。

试排不保存方案、不占用材料、不写库存。读取库存快照后在锁外执行求解，结束后检查库存整体版本；任务版本或合格数量基线失效、计算期间有业务更新时返回 409。每实例最多同时运行一次推荐，忙碌返回 503。关闭窗口不会强制中止已发出的服务器计算，迟到结果不会重新打开或覆盖当前窗口。

装载前重新读取库存，并比较推荐时的材料身份、尺寸、状态及疵点。变化时保留原预览，要求重新计算。正式求解和报工继续使用原有库存与任务校验；推荐不构成库存预留或可直接报工的方案。

- Java 新增 10 项：真实矩形与横切内核、排序与同名需求、混合宽度生产接续、避疵与修边、旋转与小数精度、只读文件对比、任务/库存冲突、报工后续配及撤回、数量上限、未评估范围、引擎不可用和 HTTP 契约。

- 使用临时库存和隔离浏览器数据；不替代生产库存写入、现场机台与实物裁切验收。
