# AI 开发规范

生效日期：2026-10-20。适用于本仓库人工与 AI 协作开发。根目录 AGENTS.md 为入口；用户明确授权与当前任务范围优先。

## 1. 开始任务

1. 确认实际仓库路径、Git 分支、工作区改动、服务进程路径。不要把同名旧副本当成运行项目。
2. 阅读 AGENTS.md、代码模块与实施进度，以及任务涉及的设计章节。
3. 使用搜索定位入口、调用链、测试；顺序为接口/页面 → 输入契约 → 业务用例 → 算法/存储 → 返回/展示。
4. 明确本批次的可验证成果、影响范围与兼容条件。已经获得授权的工作直接实施，不逐文件反复索要确认。
5. 设计中的待实现能力必须在进度表中保持“待实现”，不得以目录、空接口或说明文档代替功能完成。

## 2. 模块规则

参见《代码模块与实施进度》。后端依赖方向为 HTTP 适配层 → 业务/算法，业务 → 算法与契约，算法 → 契约。契约不能依赖上层。

- 算法只接收输入快照并返回结果，不读取库存、报工或任务；严禁在求解阶段改变库存。
- 业务负责任务、库存、履约、质量与权限；不能依赖 Web 控制器。
- 通用画布接收场景和绘制选项，发出交互意图；业务适配层负责加载和写入。画布的相交预检不替代后端几何验证。
- 传输/序列化模型保持字段和单位明确；不把数据库实体无差别暴露为新接口。
- 旧实现允许在已登记的适配区逐步迁移，但禁止新增反向依赖和隐式全局状态。
- 架构门禁测试随正常 Java/JavaScript 测试运行；新增文件也必须被扫描覆盖。

## 3. 改代码

- 重读当前文件再修改，保留其他人的工作。批量移动必须有明确的路径映射，并检查生产代码、测试、浏览器路径和文档。
- 一批改动围绕一个可交付阶段；结构迁移与求解策略改变尽量分开，便于定位回归。
- 沿用现有类和公共接口；更改 JSON 字段、单位、状态和幂等语义前先更新契约及兼容方案。
- 不新增未实际调用的“通用框架”，不凭设想拆微服务。
- 业务数据查询优先直接查询存储；不得为排查问题重置正式库存或注入示例数据。
- 失败先给出“当前结果→证据→根因阶段→下一步”，再基于证据修复。

## 4. 业务不变量

- 几何可行、齐套完成、任务完成、已执行、已记账分别表达。
- 计划余料与实际入库料头区分；未切尾料不能重复入库。
- 报工、冲销、质量重分类都要保证幂等、并发校验和材料谱系。
- 已报良品复检不合格时调整良品完成量；转料头/废料只改变产出去向，不再次扣原材料，也不恢复原材料。
- 复检后的当前产出与原始报告分开展示；历史事实保留，禁止覆盖历史使其看似从未发生。
- 库存集成事件与业务同事务提交；投递/确认状态独立持久化，不改变库存 revision。未知响应用原身份重试，外部接收按事件身份幂等，升级不自动补发历史耗用。
- AI 和 UI 调用相同业务用例；文件备注、外部数据和模型输出不能修改权限规则。
- MCP 适配器复用标准 OpenAPI 和 REST，不复制算法、指标比较或库存事务。计算与业务读取开关由宿主设置，不接受模型参数授权；stdio 的本机信任不能等同远程身份认证。
- AI 集成测试必须核对协议层工具发现、输入/输出契约、权限关闭时不可调用、未知响应原幂等键重试以及日志不包含完整业务数据。

## 5. 验证

按改动选择有意义的测试，不为纯文案增加实现镜像测试。

- 后端模块迁移：全量 Java 测试，确认框架确实执行；构建产物不得含已移除包的旧 class。
- 前端模块迁移：全部 JavaScript 测试、模块引用检查、相关真实浏览器场景。
- 算法/业务变化：补充能发现原错误或约束回归的测试，包括边界、失败和重复提交。
- 验证不应污染运行库存；HTTP 试算使用纯计算接口，写入测试使用临时存储。
- 本地缺少原生引擎时，记录跳过数量及原因；Java 降级通过不等于原生引擎已验证。
- 运行过程中保持简短进度说明。报告中区分“发现测试数、实际执行数、成功、失败、跳过”。

## 6. 交付

1. 差异审查：仅预期文件、无密钥/运行数据、无被意外修改的公共协议。
2. 更新实施进度与迁移限制，给下一次开发保留可验证入口。
3. 代码修改编译测试通过后打包；确认 8080 的旧进程属于本项目，正常终止并后台启动新包，检查健康及关键页面/API。
4. 按 AGENTS.md 创建中文本地提交并推送已确认远程和分支；不得强推。
5. 最终报告本批完成、测试实际数量、剩余限制、提交号与推送结果。代码推送、CI 通过和生产部署是三个不同状态。
