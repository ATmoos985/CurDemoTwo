# 库存流水与内部对账

已接入内置二维库存与需求闭环。每次成功业务写入在同一事务内追加不可变记录，并更新余额；流水保存变化前后值、几何和谱系，可重放并核对当前余额。文件模式为单实例；MySQL 模式采用全局版本 CAS、数据库事务和 V5 流水表。

## 账户与事件

| 账户 | 记录内容 |
| --- | --- |
| `ROLL` | 母卷档案、几何、当前剩余和耗用长度、检验/疵点、库位；不记录由查询派生的料头数量/面积 |
| `REMNANT` | 料头实测尺寸、面积、状态、库位、父料与报工/复检来源 |
| `DEMAND` | `任务 ID/需求行 ID`，需求属性、要求数量、累计净良品数 |
| `REPORT` | 原报工与后续复检、冲销状态；原流水版本永久保留 |
| `CHECKPOINT` | 期初迁移版本标记，即使空库也有明确起点 |

事件包括 `MIGRATION_OPENING`、`DEMAND_ADJUSTMENT`、`CUT_REPORT`、`CUT_REPORT_BATCH`、`QUALITY_DISPOSITION`、`REPORT_REVERSE`、`ROLL_RECEIPT`、`ROLL_ARCHIVE_UPDATE`、`INSPECTION`、`REMNANT_RECEIPT`、`REMNANT_ISSUE`、`REMNANT_SCRAP`、`REMNANT_STATUS_ADJUSTMENT` 及明确标记的演示数据变动。

预约状态与操作历史保留在执行单中。本账本的需求余额是要求量和实际净良品量，不把候选方案或动态过期预约算成完成量。尚未提供独立盘点单/移库单及审批；旧档案修改记录完整前后值，不能视为这些管理流程已经完成。

## 迁移和原子性

旧文件或旧数据库未记录完整历史时，第一次成功业务写入先为原有事实建立 `MIGRATION_OPENING`，再记录本次变动，两者一同提交。查询不会自动迁移；服务启动的示例材料检查属于已有业务写入，因此默认演示模式启动会完成期初登记。

期初的材料余额和历史报工按实际已有内容保存，不把它们伪装为逐笔入库或裁切事件。迁移前应备份；对账只能证明期初之后的链条和当前已知事实，不能证明旧系统未记录的历史正确。

报工、批次报工、复检和冲销经过同一 `RemnantService` 事务。预演、试排及重复提交不追加业务流水；保存失败同时回滚期初、流水、库存、需求、报工和执行单。JDBC 只对新增流水执行 INSERT，存储端拒绝截短、重排、替换历史及重复身份；文件端也检查原历史前缀。

这是应用层的只追加约束，不代表拥有数据库管理权限或本机文件写权限的人不能篡改数据。内部对账能发现链条/余额差异；尚未提供外部签名、防篡改存储或数据库权限部署方案。

## 字段和冲销

- `sequence` 是全账本递增游标，`transactionId` 将一次操作的多账户变动关联起来。
- `businessId` 为可用的任务/材料/报工号；没有已分配业务号的创建操作使用该事务号。
- `beforeVersion/afterVersion` 为库存全局提交版本，不是单个账户版本；期初使用迁移前版本。
- `beforeJson/afterJson` 为规范化 JSON 字符串，保存完整前后事实；null 表示该账户当时不存在。尺寸 mm、面积 m²、需求件数分别记录，不相加。
- `sourceReportIds` 仅关联实际影响该账户的报告。`reverses` 仅引用同账户的原流水/期初；批次合并余额可以部分冲销，实际抵消量以本条前后值为准，不表示整条历史被删除或完全抵消。
- 尚无认证身份的旧入口标记为 `UNAUTHENTICATED_LOCAL`；复检申报人员带 `DECLARED:` 前缀，不能当成已验证登录身份。

已记账报告不允许通过演示重置物理删除。合法冲销追加新流水并保留原记录；有后续流转/预约或复检处置时继续执行既有保护。复检冲减良品并重分类产出，不能再次扣母卷，也不能恢复已加工母料。

## 查询与对账

- `GET /api/v2/inventory-ledger?aggregateType=ROLL&aggregateId=...&after=0&limit=100`
- `GET /api/v2/inventory-ledger/reconciliation`

分页 `limit` 为 1–500，返回 `items`、`nextCursor`、`hasMore` 和当前 `revision`。下一页使用上一页游标；筛选参数必须保持一致。没有修改/删除流水接口。

对账返回 `NOT_INITIALIZED`、`BALANCED` 或 `MISMATCH`，覆盖：

1. 流水序号连续、每个账户前后链条连续，重放最终值与当前余额一致。
2. 需求净良品在 0 与要求量之间；母卷总长 = 已用长度 + 剩余长度。
3. 每张有效报告的领用面积 = 当前良品 + 尚未处置不良品 + 回收料头 + 其他废料与损耗。原报工的 `wasteArea` 包含不良品，对账时先分离，避免重复计数。
4. 复检将对应面积从原分类转出；记录面积差额，超出数值容差 0.000001 m² 或出现负分类时报异常。历史面积字段不足时明确返回无法核对的项。

发现流水与余额不一致后，后续业务记账拒绝继续覆盖差异；查询保留异常证据，不自动“修平”。当前对账是内置库存和已存业务事实的核对，未接外部 WMS、称重计量、一维执行库存或跨系统凭证。API 的具体字段同时收录于 `/api-v2/openapi.json`。

## 页面入口

`/analysis.html` 展示实际报工面积分解与内部对账，`#ledger` 直达流水。查询不写入，流水按 sequence 游标载入，筛选对象类型和精确编号。导出只覆盖页面已载入的记录，不声称全量导出。

实际良品产出率按 `Σqualified / Σconsumed` 计算，可回收率按 `Σrecovered / Σconsumed` 计算；使用对账服务已扣复检后的面积，不能重复扣减。加工投入是每次报工的领用面积，料头再用会再次计入投入，因此不是唯一采购原料消耗。当前只汇总二维业务，旧一维不混入。NOT_INITIALIZED、MISMATCH 或无完整面积数据时不显示百分比；保留异常编号与逐单证据。读取失败明确提示已有值可能过期。
