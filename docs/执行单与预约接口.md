# 执行单与预约接口

本阶段接入已保存的二维业务任务方案。计算作业、候选材料、试排和草稿均不占库存；下达才预约整卷或整块料头及对应需求。接口与原有报工共用业务事务，不能绕过预约直接从旧入口消耗材料。

## 调用顺序

1. 使用任务接口保存需求，通过 `/api/solve` 得到已有任务的 `planId`。
2. `POST /api/v2/execution-orders`，请求头 `Idempotency-Key` 为 8–128 位字母、数字或 `._:-`：

   ```json
   {"planId":"已有业务方案 ID","station":"裁床 A"}
   ```

3. 返回草稿 `id` 和 `version: 1`。下达调用 `POST /api/v2/execution-orders/{id}/release`：

   ```json
   {"operationId":"release-20261020-001","expectedVersion":1,"reservationSeconds":1800,"reason":"下达生产"}
   ```

4. 开工调用 `/{id}/start`，使用返回的新版本、独立操作编号，`reservationSeconds` 填 0。开工后预约不自动过期，也不能取消。
5. 实际加工后调用 `/{id}/reports`。正文沿用《切割任务与对接接口》的 `CutReport`：方案 ID、实际长度、合格件数、逐件结果和实际回收料头。成功后执行单变为 `REPORTED`，预约释放，仅合格件累计完成需求。异常和未切件仍需后续排料。
6. 未开工可调用 `/{id}/cancel`，版本与操作编号规则相同，时长填 0，原因必须非空。

`GET /api/v2/execution-orders?taskId=...` 查询列表；`GET /api/v2/execution-orders/{id}` 查询单个。查询返回 `execution`、`effectiveState`、`reservationActive`、`allowedActions`。后者按 release/start/cancel/report 返回 allowed 与 reason；仅作当前快照下的操作提示，提交仍重新校验。创建和命令直接返回执行单。

## 状态与冲突

- `DRAFT → RELEASED → RUNNING → REPORTED`；报工依法撤回后为 `REVERSED`。实物已加工不能以取消代替报工，复检判废也不能恢复母料。
- `RELEASED` 到期在查询中为 `EXPIRED`，持久化的 `state` 保留原始 `RELEASED`；通过 `effectiveState` 判断。可以重新下达或新建替代草稿，同方案不能同时有两个有效预约。
- 下达时核对任务版本、材料快照、可用范围、母卷检验状态及剩余需求。整卷预约暂不支持不同区间并行加工。
- 预约中的任务和材料不能修改；不得取消/调整已下达方案。报工撤回不能删除被后续执行单预约的派生料头，演示重置不能删除已有执行追溯或任务报工。
- 同一创建键只能对应相同方案和工位；同一命令编号必须携带相同动作、原版本、时长和原因。成功重试返回当前状态，不重新执行动作。
- 新报工保存完整规范化请求内容，同方案不同内容返回冲突；历史回执未存请求内容，继续原幂等语义，不伪造历史证据。数组顺序、空值和省略列表等差异可能视为不同内容，重试应复用原正文。
- 不存在资源或输入不合法为 400，状态、版本、幂等或预约冲突为 409。JSON 拒绝未知字段、重复键、浮点转整数、字符串转数字及尾随正文；正文最多 262144 字节。

## 存储与边界

文件模式仍为单实例。JDBC 模式 Flyway V4 添加 `execution_order`，执行单与库存、报工、需求共用快照版本 CAS 和数据库事务；并发失败重新查询后再决定重试，不能盲目生成新幂等键。JDBC 预约以数据库时间为准，每次业务操作采样一次；文件模式使用本机时间。

工作台已接入创建、下达、开工、取消、只读恢复和实切报工，命令在本机保存原幂等身份用于断线重试。已有连续工位暂存仍走兼容批报，不能与有效执行单混报。不可变库存流水与内部对账见对应文档；外部库存锁和认证权限仍待实现。标准一维计算结果尚不能直接生成本接口执行单；其任务与产出模型后续接入。不能将本接口视为整体管理改造完成。

## 任务管理汇总与直达入口

`GET /api/cutting/task-summaries` 保留原有字段，增加 `status`、`reserved`、`availableToPlan`、`runningCount`、`releasedCount`、`expiredCount`、`materialReservations`、`nextAction`。一次读取使用同一库存版本与预约时钟，不产生库存写入。

- `completed` 为扣除复检降级、排除冲销后的净良品；`reserved` 只汇总有效 RELEASED/RUNNING；`availableToPlan` 逐需求取 `max(0, quantity - completed - reserved)` 后求和。预约不是实际完成。
- 状态优先级为 RUNNING 对应 `REPORT_PENDING`、全部履约 `COMPLETED`、仍需处理的过期预约 `ATTENTION`、有效预约或当前版本待定方案 `EXECUTION_PENDING`、其余 `PLAN_PENDING`。状态表示任务下一步，不代替执行命令校验。
- `expiredCount` 按仍为当前版本 PENDING 的方案去重。同方案存在新草稿或有效执行单时，旧过期尝试不重复提示；已全部履约不因旧过期记录重开。旧执行单重新下达后再过期仍提示。历史事件继续保留在执行记录中。
- `pendingCount` 是方案数，包含候选方案，不能解释为待报工数。`materialReservations` 返回有效占用的 executionId、materialId、materialType、station、state。
- `nextAction` 仅为页面只读入口建议：workspace / plans / executions / reports；实际操作继续读取执行单 `allowedActions` 并在提交时重新验证。

`/tasks.html` 提供状态、任务号、名称、材料与来源单号筛选。`/index.html?taskId=...&view=executions|plans|reports` 只读装载指定任务并可打开记录；`?newTask=1` 创建未保存的本机工作区。显式链接优先于上次任务与自动草稿恢复，草稿记录保留在“本机草稿”中；任务不存在或读取失败显示阻断错误，不静默打开其他任务。成功切换/保存后同步显式任务 URL。没有显式参数的旧工作台继续优先恢复活动草稿。

目前任务没有完整创建/编辑时间，页面不伪造“最近编辑”或截止日期。列表仅覆盖已保存的二维生产任务；一维业务任务与统一导航后续接入。
